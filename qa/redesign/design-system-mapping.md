# Design-system mapping for the proposed workspace

The redesign retains AppShell, Header, Sidebar, the breadcrumb component, the local Manrope font resources and the existing theme-variable system. New navigation, scope and detail objects change the workflow structure; they do not introduce a new brand or palette.

The common layer is `src/modules/hindsight/redesign/components/ui.tsx` and its CSS module. Screens should consume it rather than define another button/card/table language.

- **Buttons:** the shared Button delegates to the exact recovered Impact Button through the existing adapter. Primary uses vendor primary; neutral secondary maps to the existing tertiary outlined treatment; ghost maps to vendor text; destructive uses the vendor destructive type. Large is 32 px, medium 28 px and small 24 px. The vendor supplies the original 8 px radius, Manrope 14/400, 6×12 px padding, state colors, icon geometry and focus behavior. The wrapper correctly separates native `htmlType` from vendor styling `type`.
- **Primary tabs:** WorkspacePage uses the actual ImpactTabs implementation. Its original 14 px Manrope, selected 600 weight, indigo-400 text and 2 px underline are retained. A scoped flex-wrap rule is the intentional structural adaptation: the three approved primary views remain visible at narrow widths.
- **Review modes:** the actual Impact ButtonGroup supplies the existing segmented-control treatment. PLR and In-season are new options in that component.
- **Widget surfaces:** WorkspaceCard follows recovered `WidgetCard.module.css`: 12 px padding, 12 px radius, 1 px semantic border, white theme surface and the original 0 0 4 px / 18% shadow. Card headings are 14/700/21; section headings follow ItemToolbar's 16/600/24.
- **Scorecards:** label 14/400/16 and value 24/600/36 with tabular numerals follow recovered ProductPerformanceKpiCards. The six-card grid and evidence helper are deliberate functional changes replacing the horizontal carousel.
- **Tables:** text uses the existing 14 px small token and 21 px line height. Header rows are 40 px, leaf rows 44 px and horizontal cell padding 16 px, matching the recovered DataGrid and admin theme. Header/background/border/hover roles consume slate and indigo palette variables. Small illustrative native tables retain semantics and horizontal scroll; larger matrix paths must keep explicit scale limits rather than claim unbounded native-table virtualization.
- **Form controls:** native semantic controls in the new draft/filter forms map to the recovered input geometry: 32 px height, 8 px radius, slate-300 border, slate-800 content, Manrope 14/500 and 12 px inline padding. Labels use the 12 px token. Select chevrons use the recovered local select-chevron.svg. Native controls are retained where they provide typed/date inputs and deterministic keyboard interaction; they do not define a new visual style.
- **Color:** all shared redesign CSS uses existing theme/palette variables. Indigo is the established interactive accent; slate carries text/borders/surfaces; semantic emerald/amber/rose states are paired with visible text. Iris uses existing iris/purple tokens. There is no parallel hardcoded set of almost-identical colors.
- **Spacing:** page gutters use the existing 24 px desktop / 16–12 px narrow pattern. Shared composition uses the existing 4/8/12/16/24/32 px steps. Detail pages and the 448/640 px Iris panel with bounded pointer/keyboard resizing are new compositions within those roles.

The global scope drawer intentionally has a fixed footer, wrapping scope summary, multi-group draft state and atomic Apply/Cancel. Full Item/Store/Pair/Case workspaces intentionally replace stacked drill drawers. Iris retains one existing header trigger and uses a scoped interceptor to open the new contextual presentation; adjacent modules continue to use the recovered host.

Visual review remains required on the actual composed screens. Reusing tokens and components alone does not prove a complete viewport or interaction match. Phase-one archives remain unchanged and retain the exact original UI for comparison.

The approved primary structure is Overview / Deep Dive / Decisions. The Deep Dive preset selector and Overview Summary / Sales Mix segmented control reuse the recovered select and ButtonGroup. The scope filter uses the existing Modal focus trap and restores focus on Escape/Cancel. New workflow structure is intentional; page gutters, cards, text, button geometry and semantic state colors follow the existing system. PLR calendar/L0 is locked with a contiguous review cutoff; tactical calendar remains flexible.
